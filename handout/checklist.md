# Data Science Interview: One-Page Checklist

## 1. The basics

- [ ] Email is firstname.lastname@gmail.com (UNC address for school outreach only)
- [ ] Resume is one page, reverse chronological, no photos or graphics, saved as a PDF
- [ ] Every bullet is action verb + what I did + measurable result
- [ ] LinkedIn and GitHub URLs are on the resume and match it
- [ ] Proofread out loud; tense and date formats are consistent

## 2. GitHub in the age of AI

- [ ] Two or three polished repos are pinned, not fifteen abandoned ones
- [ ] Each README covers the problem, approach and why, what failed, results vs. baseline, next steps
- [ ] Data is real and messy (Kaggle, CFPB, Census, NC open data), not Titanic or Iris
- [ ] Baseline, proper splits, leakage checks, calibration, and error analysis are shown
- [ ] Explainability (e.g., SHAP) shows what the model learned and whether it makes sense
- [ ] An AI usage note says where I used AI and how I verified it, and I can explain every line

## 3. STAR that lands

- [ ] Six to eight stories are written as outlines, each mapped to several questions
- [ ] Themes covered: conflict, ambiguity, failure, deadline pressure, influencing without authority, mistakes
- [ ] One failure story: what did not work and what I changed
- [ ] Time split: Situation and Task 10-15%, Action about 60%, quantified Result the rest
- [ ] I say "I," not "we," in the Action

## 4. Technical prep

- [ ] SQL: joins, window functions, CTEs, and deduplication logic
- [ ] Stats: A/B tests, p-values and confidence intervals in plain English, bias and variance, class imbalance
- [ ] ML: why gradient boosting works, when not to use deep learning, how to handle leakage
- [ ] One full case practiced out loud, from framing through deployment and monitoring
- [ ] I think aloud, because interviewers grade the process

## 5. Standing out

- [ ] Two sharp questions for the interviewer (model drift monitoring, DS and engineering handoff)
- [ ] A concise follow-up email that references something specific from the conversation
- [ ] One industry learned well, including its data and regulations
- [ ] I can talk about decisions the business would make, not just models

**Build things you can explain.**
